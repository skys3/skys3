# Why each ceph/s3-tests test that subset.txt does not select is left out
# (plan M7-01): `## <kind> | <group> | <why>`, then rules, as
# skys3_s3tests.py describes. A test belongs to the first rule that
# matches it, so the narrow rules come first. The kinds:
#
# - unsupported: a feature SkyS3 does not support (design section 11
#   rejects most of them with an error, which the gateway's
#   tests/compatibility.rs checks).
# - divergence: SkyS3 answers a supported request differently from what
#   the test expects, by design; each is described in the compatibility
#   matrix. None has been checked against AWS S3 itself.
# - assumption: the test relies on something of the RGW test setup that
#   SkyS3 does not have, such as several accounts, bucket owners, or a
#   lifecycle debug clock; or on client behaviour the pinned botocore
#   lacks.
# - open: a gap in a supported feature too large to fix in M7-01, kept
#   visible as an open point of the matrix until it is fixed and the
#   tests move to subset.txt.
